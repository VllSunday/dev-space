# Как добавить блок флоу

Блок — шаг процесса с фиксированным набором выходов. Исполнитель флоу (`flows/engine.mjs`) о
конкретных блоках ничего не знает, поэтому новый блок добавляется без его правки. Способов два.

## 1. Блок из плагина: настройка без кода

Подходит, когда новый шаг — частный случай уже существующего: «Работа» с готовым заданием,
«Действие» с конкретной операцией, «Проверка фактов» с конкретной проверкой.

В `plugin.json`:

```json
{
  "plugin": 1, "id": "linear", "name": "Linear", "description": "…",
  "blocks": [{
    "id": "comment",
    "title": "Комментарий в трекер",
    "summary": "оставляет комментарий к задаче; делает код",
    "base": "action",
    "with": { "need": "${need}", "operation": "comment", "text": "${text}" },
    "params": {
      "need": { "type": "need", "title": "Трекер задач", "required": true },
      "text": { "type": "text", "title": "Текст комментария", "required": true }
    }
  }]
}
```

- `base` — базовый блок: `input`, `work`, `review`, `ask`, `person`, `parallel`, `facts`, `action`.
- `with` — параметры базового блока. `${имя}` подставляет параметр, который задаёт автор флоу.
- `params` — параметры нового блока: `text`, `number`, `enum` (со списком `values`), `role`, `need`.
- Выходы наследуются от базового блока.

После установки плагина блок сразу:

- появляется в редакторе флоу в списке «Добавить шаг» и в справочнике агентов (`devspace help`);
- используется во флоу по имени `плагин/блок`: `{ "block": "linear/comment", "with": { … } }`;
- проверяется теми же правилами: лишний или пропущенный параметр — проблема, флоу не запустится;
- если плагин удалить, флоу с этим блоком покажет «блок не найден» и не запустится.

Проверено тестом `a plugin adds a block that flows can use at once…` в
`desktop/service/test/flows.test.mjs`.

## 2. Встроенный блок: файл с кодом

Подходит, когда нужно новое поведение. Положите файл в `desktop/service/flows/blocks/`; реестр
подхватывает все файлы папки при запуске сервиса.

```js
// desktop/service/flows/blocks/wait.mjs
export default {
  id: 'wait', title: 'Пауза', summary: 'ждёт, пока агент освободится',
  params: { role: { type: 'role', title: 'Кого ждём', required: true } },
  outputs: [{ id: 'free', title: 'Освободился' }, { id: 'late', title: 'Не дождались' }],
  // Дополнительные проверки файла флоу. Возвращает список проблем.
  check(step, flow) { return []; },
  // Вход в шаг. Вернул { output } — шаг закончен; ничего не вернул — шаг ждёт сигнала.
  async enter(ctx) {
    const state = await ctx.call('agent.wait', { id: ctx.run.roles[ctx.params.role].sessionId, timeout: '600' });
    return { output: state.state === 'свободен' ? 'free' : 'late', summary: state.state };
  },
  // Сигналы: { type: 'submit' } — агент сдал шаг, { type: 'decision' } — решил человек.
  async signal(ctx, signal) {},
};
```

Что даёт `ctx`:

| Поле | Что это |
|---|---|
| `ctx.params` | параметры шага из файла флоу |
| `ctx.run.item` | вещь, которая едет по флоу |
| `ctx.run.results`, `ctx.lastResult()` | результаты прошлых шагов |
| `ctx.again`, `ctx.came` | шаг пройден повторно; откуда пришли и с каким пояснением |
| `ctx.call(имя, параметры)` | команда из пула (`commands.mjs`) — единственный способ что-то сделать |
| `ctx.tell(роль, { task, outputs })` | выдать задание агенту и ждать сдачи |
| `ctx.waitPerson({ question, summary, proposal })` | остановиться и ждать решения человека |
| `ctx.state` | память шага на время одного захода |

Правила, которые держит исполнитель:

- блок может вернуть только выход из своего списка `outputs`; иной выход останавливает флоу;
- агент сдаёт шаг только выходами, которые блок перечислил в `ctx.tell`;
- переходы, пределы возвратов и общий предел передач считает исполнитель, а не блок;
- блок с `agent: true` считается шагом агента (для полосы шагов и предела передач), с
  `person: true` — шагом человека.

Параметры описываются типами `role`, `need`, `step`, `text`, `enum`, `number`: по этому описанию
редактор рисует форму, а проверка флоу отклоняет лишнее и недостающее. Подписи значений для
редактора задаются в `labels`.

Что блок сдаёт на проверку кодом, описывается в `flows/checks.mjs`: там же текст, который агент
видит в задании («что должен сдать»), и сама проверка.
