# Решения, которые ждут владельца

Я не останавливал работу ради вопросов: в каждом месте выбран разумный вариант, и он уже работает.
Ниже — что выбрано, почему и как поменять. Сверху самое важное.

## 1. Шаг флоу отправляет задание агенту сам

- **Вопрос.** В PRODUCT.md был принцип «неотправленное задание остаётся в терминале на проверку».
  Флоу из нескольких шагов так работать не может: он остановится на первом же шаге.
- **Выбрано.** Запуск флоу — явное действие человека, после него шаги отправляют задания сами.
  «Отдать агенту» с доски по-прежнему только вставляет текст и ничего не отправляет.
- **Почему.** Иначе флоу не идёт сам; а ручная передача карточек осталась под контролем человека.
- **Как поменять.** В `flows/engine.mjs: tell` отправка идёт через `host.send` (с отправкой). Можно
  добавить параметр блока «Работа» «вставить и ждать Enter» и завести его по умолчанию.

## 2. Разрешение агенту на команду `devspace`

- **Вопрос.** Агент сдаёт шаг командой `devspace step done`. Claude Code в обычном режиме спрашивает
  разрешение на каждую команду оболочки. AGENTS.md запрещает менять права агента без владельца.
- **Выбрано.** По умолчанию ничего не меняется: Claude спросит разрешение, человек ответит «больше не
  спрашивать». В окне запуска флоу есть галочка «Не спрашивать разрешение на команду devspace»: тогда
  новые сессии Claude Code получают `--allowedTools Bash(devspace:*)` — и только это. Если у
  пользователя уже включён режим без подтверждений, галочка не показывается.
- **Почему.** Право узкое (одна команда), но это всё же изменение прав — решать вам.
- **Как поменять.** Настройка `allowDevspaceCommand` (по умолчанию `false`), `agents.mjs`.
- **Codex.** В песочнице Codex без сети команда не достучится до сервиса по HTTP. Для этого сделан
  запасной канал: запрос кладётся файлом в закрытую временную папку, сервис отвечает файлом. С
  настоящим Codex это не проверено (см. отчёт).

## 3. Предложение страницы принимается и после других правок

- **Вопрос.** Раньше предложение, созданное для прошлой версии хранилища, отклонялось. Теперь версия
  меняется от любого движения зоны, и почти любое предложение оказалось бы «устаревшим».
- **Выбрано.** Предложение только добавляет страницу и ничего не перезаписывает, поэтому оно
  применяется, если его источники ещё существуют. Отклоняется только предложение «из будущего».
- **Как поменять.** `devspace.mjs`, действие `apply-proposal`.

## 4. Подключения без кода

- **Вопрос.** Плагин-подключение должен ходить в сеть, но не должен получать ключи и диск.
- **Выбрано.** Операция подключения — шаблон HTTP-запроса и правило разбора ответа. Запрос делает
  ядро: только `https`, только объявленные адреса, ключ подставляет само. Кода у подключения нет.
- **Цена.** Не покрыты вход через OAuth, постраничная выдача и сложная логика; «новая задача» пока
  определяется при запуске флоу («следующая, которую никто не начал»), фонового слежения нет.
- **Как поменять.** Расширять `plugins/operations.mjs` (страницы, OAuth) либо разрешить подключениям
  код в отдельном процессе — это отдельная большая работа.

## 5. Формат флоу — JSON

- **Выбрано.** Один файл `*.flow.json`: его читает код без новых зависимостей, он правится блоками,
  текстом и агентом. YAML из записи 9 ноября был только иллюстрацией.
- **Как поменять.** Разбор и запись сосредоточены в `flows/engine.mjs` (`library`, `save`) и в
  `src/flows/FlowsPlace.tsx: serialize`.

## 6. Что стало с боковой навигацией и Wiki

- **Выбрано.** Боковая панель проекта убрана. Первый экран проекта — доска. Wiki-страница осталась
  документом в зоне «Документы»; темы стали зонами; прежняя лента темы — это вид зоны «Лента с
  описанием». Плотная навигация доступна как вид «Навигатор проекта» («Добавить → Зона»).
- **Что потерялось.** Цвета пунктов навигации больше нигде не видны (цвет теперь у зоны); значок
  темы показывается у зоны. Проект открывается на доске, а не на главной странице.
- **Как поменять.** Если нужна постоянная навигация слева от доски — это одна зона с видом
  `core/outline`; её можно сделать закреплённой панелью.

## 7. Зона и тема

- **Выбрано.** Зона для заметок и файлов создаёт свою тему: её вещи остаются вместе на всех досках.
  Удаление зоны не удаляет ни тему, ни вещи. Переименование зоны переименовывает тему, пока их
  названия совпадают. «Подборка» — зона со ссылками на вещи из разных мест.
- **Как поменять.** `devspace.mjs`: `zone-create`, `zone-update`, `delete-topic`.

## 8. Доска без масштаба колесом

- **Выбрано.** Три уровня — это и есть масштаб: доска, зона, вещь. Зоны двигаются и тянутся по
  сетке 20 px, пустое место перетаскивается. Плавного зума и бесконечного холста нет; зоны могут
  перекрываться, если их так положить (вид «Ровные колонки» это исключает).
- **Почему.** Меньше способов потеряться; движок — обычная вёрстка, без новой зависимости.

## 9. Блоки из плагинов — настройка, а не код

- **Выбрано.** Плагин добавляет блок как настроенный вариант базового (`base` + `with` + свои
  параметры). Блок с собственным кодом — это файл в `desktop/service/flows/blocks/`.
- **Почему.** Код блока исполняется в сервисе с правами приложения; чужому коду там не место.

## 10. Справочник для агентов

- **Выбрано.** Каждая сессия получает команду `devspace` в `PATH` и свой токен; справочник —
  `devspace help`. О команде агент узнаёт из первой строки задания флоу. В системную подсказку CLI
  ничего не добавляется.
- **Как поменять.** Можно добавлять одну строку через `--append-system-prompt` (Claude Code) и
  аналоги; это тоже изменение настроек агента.

## 11. Каталог плагинов

- **Выбрано.** Каталог — папка `desktop/service/plugins/catalog` внутри приложения: Linear, «Чертёж»,
  «Прогресс». Ничего из неё не установлено, пока вы не нажали «Установить». Сетевого списка нет.
- **GitLab.** Не сделан: ему нужна смена статуса с разными запросами для каждой группы, а это
  требует ещё одной возможности в шаблонах операций. Linear сделан полностью.

## 12. Передача длинного чата

- **Изменилось.** Агент теперь сам записывает заметку в файл и сдаёт шаг; раньше сервис вырезал её
  из ответа в чате. Зато передача работает с любым агентом, а не только с Claude Code и Codex.

## 13. Что не делалось в этом этапе

Английский интерфейс новых экранов; доска в мобильном виде; виды уровня «вещь» из сторонних
плагинов (сейчас это встроенные компоненты); обмен настройкой по ссылке; сервер для команд.
Архитектура им не мешает: виды, блоки и подключения уже описываются файлами.
