# Markdown alignment and space deletion

- Fixed a class collision: heading prose blocks inherited the section toolbar's 32px horizontal padding and large vertical padding. Prose modifiers now use their own namespace, including the quote style. Markdown heading levels 1–6 have zero inline margin, padding and first-line indent. Stored Markdown, block IDs, lists, code and quotes are preserved.
- Space settings now expose Delete with a confirmation and agent destination. Supports deleting the original local space; the last space is retained with an explanation. Running, closed, legacy and saved assignments move without changing CLI sessions, their native IDs, working folders, right-side project or destination pane layout. Stale destinations and repeated deletion are rejected before mutations.
- Space deletion also offers “Do not transfer — close agents”. The existing close-chat path stops only source-space open agents and retains their sessions/native IDs/history and files. Destination selection is hidden in this mode. UI explains process termination and provides the affected chat list. Failed closure retains the source space and assignments for retry; a partially closed batch may contain already closed chats. No permanent history deletion is introduced.
- 27 related model, page-flow, attachment and agent-space tests pass, including authenticated deletion in both modes, persistence across restart, history preservation, empty spaces, and close-failure handling. Tests use synthetic sessions and injected closure; no real CLI process is stopped.
- TypeScript and Vite build and staged runtime verification are recorded in the preview manifest. Native launcher sources are unchanged.
- Visual/native interaction is not verified in this environment: prior browser launch was blocked by spawn EPERM. No user agent or project was opened or stopped for testing.
